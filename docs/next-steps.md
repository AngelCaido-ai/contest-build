## Идеи на будущее

### Sweep deposit-кошельков через V5 batch actions

После release/refund на deposit-кошельке остаётся ~0.01-0.015 TON (неиспользованный reserve за комиссию). Эти средства принадлежат рекламодателю.

**Текущий вариант (V4r2):** отдельная фоновая задача `sweep_completed_deposits`, которая через N минут после завершения сделки отправляет остаток обратно рекламодателю с `send_mode=128` (полное опустошение кошелька).

**Оптимальный вариант (V5):** использовать batch actions — в одной транзакции отправить и payout/refund, и sweep остатка. V5 поддерживает несколько исходящих сообщений в одной транзакции через `pack_actions`. Последнее сообщение с `send_mode=128` заберёт весь оставшийся баланс. Это исключает необходимость отдельной sweep-задачи, задержку и дополнительные поля в модели.

Пример логики для release:
- Action 1: отправить `deal.price` владельцу канала (mode 0)
- Action 2: отправить остаток рекламодателю (mode 128)

Для refund batch не нужен — достаточно одного перевода с mode 128, т.к. и price, и остаток идут рекламодателю.

### Убрать поддержку V5, оставить только V4r2

Сейчас код поддерживает два варианта подписи (v4r2 и v5), переключаемых через `TON_WALLET_VERSION`. При этом deposit-кошельки всегда создаются как v4r2. Двойная поддержка усложняет код без реальной пользы.

Что сделать:
- Удалить `_is_wallet_v5_version()`, `_wallet_from_key_v5()`, `_wallet_v5_network_global_id()`, `_create_transfer_boc_v5()` из `ton_escrow.py`
- Убрать все `if _is_wallet_v5_version()` ветки из `send_payout()` и `send_refund()`
- Удалить `ton_wallet_version` из `config.py` и `.env.example`
- Убрать импорты pytoniq v5 (`WalletV5R1`, `WalletV5WalletID`, `WALLET_V5_R1_CODE`)
- Обновить тесты: убрать skip-условия для v5 и v5-специфичные кейсы
- При переходе на V5 в будущем — реализовать заново, уже с batch actions и sweep

### Полный переход на V5 (далёкое будущее)

Когда экосистема V5 стабилизируется — перевести все транзакции на V5. Что это даёт:
- **Batch actions** — несколько исходящих сообщений в одной транзакции (payout + sweep в одном вызове, без отдельной задачи)
- **Gasless** — возможность оплаты комиссий через relay в жетонах (актуально, если платформа начнёт поддерживать оплату в USDT/жетонах)
- **Extensions** — плагины, которые могут инициировать транзакции от имени кошелька (автоматизация без хранения ключей)

Что потребуется:
- Создание deposit-кошельков как V5 (`WalletV5R1`) вместо v4r2
- Реализация `send_payout` / `send_refund` через V5 с batch actions
- Встроенный sweep в release (Action 1: payout, Action 2: sweep mode 128) — отдельная sweep-задача не нужна
- Для refund — один перевод с mode 128 (весь баланс рекламодателю)
- Миграция: новые сделки на V5, старые deposit-кошельки (v4r2) обслуживаются legacy-кодом до завершения
- Обновление тестов под V5
