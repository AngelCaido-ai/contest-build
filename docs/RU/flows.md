# Флоу системы

## Роли и каналы взаимодействия
- Рекламодатель: создаёт заявки, оплачивает сделку, утверждает креатив
- Владелец канала: онбординг канала, листинг, принимает сделку, публикует
- PR-менеджер: управляет каналом по выданным правам
- Mini App: витрина и формы
- Бот: переговоры, аппрув, уведомления
- Backend: логика, статусы, аудит, эскроу
- Jobs/Queue: таймауты, автопостинг, верификация

## Аутентификация Mini App
1. Mini App получает `initData` от Telegram WebApp.
2. Отправляет `initData` в API.
3. Backend валидирует подпись и возвращает JWT.
4. Mini App хранит токен и использует в запросах.

## Онбординг канала
1. Владелец пишет боту `/add_channel @channel` или `chat_id`.
2. Бот проверяет, что пользователь админ канала.
3. Бот проверяет свои права в канале.
4. Bot API передаёт данные канала в backend.
5. Канал создаётся или обновляется.

## Создание listing
1. Владелец открывает Mini App и выбирает канал.
2. Указывает цену, формат и условия.
3. Backend создаёт `Listing`.
4. Listing появляется в каталоге.

## Создание request
1. Рекламодатель в Mini App заполняет бриф и фильтры.
2. Backend создаёт `Request`.
3. Владельцы каналов видят заявку.

## Создание сделки
### Из listing
1. Рекламодатель выбирает listing.
2. Backend создаёт `Deal` со статусом `NEGOTIATING`.
3. Стороны переходят в бота.

### Из request
1. Владелец откликается на request.
2. Backend создаёт `Deal` со статусом `NEGOTIATING`.
3. Стороны переходят в бота.

## Переговоры и фиксация terms
1. В боте согласовываются цена, формат, время публикации.
2. Бот фиксирует условия и переводит в `TERMS_LOCKED`.
3. Логируется `DealEvent`.

## Эскроу и оплата
1. Рекламодатель получает адрес депозита.
2. После подтверждения транзакции статус → `FUNDED`.
3. Логируется событие оплаты.

## Креатив и аппрув
1. Рекламодатель отправляет бриф/предпочтения.
2. Владелец принимает или отклоняет.
3. При принятии владелец готовит креатив и отправляет на ревью → `CREATIVE_REVIEW`.
4. Рекламодатель подтверждает → `APPROVED` или возвращает на правки → `CREATIVE_DRAFT`.

## Автопостинг
1. Планировщик проверяет `publish_at`.
2. Бот публикует пост и сохраняет `message_id`.
3. Сделка переходит в `VERIFYING`.

## Верификация доставки
1. Любая правка поста → `tampered`.
2. Периодический job проверяет доступность поста.
3. После `verification_window`:
   - если `tampered` или `deleted` → `REFUNDED`
   - иначе → `RELEASED`

## Завершение сделки
- `RELEASED`: выплата владельцу канала
- `REFUNDED`: возврат рекламодателю
- `CANCELED`: отмена из-за таймаута или отказа

## Таймауты
- `AWAITING_PAYMENT` старше `payment_timeout` → `CANCELED`

## Обновление статистики
1. Владельцу доступен запрос обновления статистики.
2. Backend пытается MTProto `stats.getBroadcastStats`.
3. Если MTProto недоступен → Bot API `getChatMemberCount`.
4. Данные сохраняются в `ChannelStats`.
